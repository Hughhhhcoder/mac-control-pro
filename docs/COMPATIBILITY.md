# 0.2.0 兼容性与验证范围

要求 macOS 14 或更新，默认提供 arm64 + x86_64 通用二进制。面向近年 Mac 的兼容方式是读取实际接口能力，不依赖某个机型固定的风扇数量或 RPM。

## 已实现的路径

| 设备或接口 | 0.2.0 行为 | 证据边界 |
| --- | --- | --- |
| 2022 年以来带风扇的 MacBook Pro，含 M4 Pro 等双风扇机型 | 分别识别风扇 ID、模式键、目标键与范围；各自控制和恢复，保留其他风扇状态 | 双风扇与模式状态由模拟传输测试覆盖；没有 M4 Pro 实机记录 |
| 受保护的 Apple Silicon 控制模式 | 先尝试直接控制；需要解锁时返回处理中，按有期限状态机等待，再确认模式和目标；失败恢复 | 受保护模式、延迟目标确认及超时回退由模拟测试覆盖，不等于所有固件支持该路径 |
| Mac mini / Mac Studio 等桌面机 | 尊重各风扇报告的正值最小与最大转速；不硬套笔记本的 1200 RPM 下限；百分比预设按各风扇范围转换 | 低转速范围和百分比转换有测试；这些桌面机型未完成物理写入验证 |
| 无风扇 MacBook Air | 硬件明确报告无风扇时显示监控状态；不生成模拟风扇或提供无意义的调速目标 | 零风扇与读取失败分别测试；未知或读取失败不会被直接标为无风扇 |
| Intel x86_64 | 通用构建及 `FS!` 位掩码控制路径，恢复一只风扇时保留其他位 | 位掩码路径由模拟测试覆盖；Intel 硬件写入未实测 |
| 读数不完整或固件限制写入 | 保留风扇及可读数据，显示缺失的范围、模式或目标能力；限制不可安全执行的控制 | 错误与只读状态有回归测试；不将读取成功等同于写入成功 |

上述范围描述代码路径，不是全部 Mac 的通过清单。机型名称、芯片代数或购买年份均不能替代实际 SMC 探测；系统与固件更新也可能改变行为。

## 控制与配置

- 内置预设使用每只风扇手动范围的百分比：0% 为该风扇可用的正值下限，100% 为其报告上限。自定义配置也可使用绝对 RPM；超范围目标不会被当作有效写入。
- schema 2 保存百分比标识，继续读取 schema 1 配置；旧配置缺少百分比标识时仍按绝对 RPM 解释。
- 正值硬件最小转速会被保留；若硬件最小值为零，则使用范围内的保守正值下限，不把百分比 0% 解释为停扇。
- 主应用须先确认助手协议、账户权限与逐风扇能力。处理中、已应用、受保护和失败是不同状态；目标完成有期限回读后，核心与助手都检查最终风扇快照，须同时满足手动模式和目标转速匹配，才报告已应用。单独目标匹配、单独模式匹配或写入返回成功都不够；寄存器确认也不代表实际 RPM 已稳定。
- P2 会话续约与释放受所有权约束。用户明确恢复自动与客户端释放自己的会话分别处理；旧版助手需要升级后才能启用新控制协议。
- 租约失效时保留同次响应的高温等恢复原因，不以历史记录覆盖无关新错误。过期状态快照不能撤销刚应用的策略；当前快照确认租约丢失时仍终止原策略，不重新申请旧目标。
- 温度反馈、系统热状态、租约与有期限读回共同约束控制。恢复最终仍须由 SMC / 固件接受，不能保证断电、内核阻塞或任意异常条件下的时间与结果。

## 安装范围

推荐完整 PKG，它将应用固定安装到 Applications，并为当前登录用户配置匹配助手。应用设置还提供内置的安装、更新和卸载包。此流程不固定 UID、不需要源码仓库；安装完成后仍单独检查固件控制能力。

没有电池的台式机不显示虚构电量。系统热状态是状态枚举，不是摄氏温度；通用 SMC 温度 key 也不保证对应独立物理传感器。正常模式的缺失值不会用演示数据补齐。

兼容性报告应包含机型、芯片、macOS、应用与助手版本、实际 RPM 和模式读回。分享前移除序列号、账户、UUID 及无关信息。
